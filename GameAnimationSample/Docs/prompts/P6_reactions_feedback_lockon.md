Play through the avatar's `UAnimInstance::Montage_Play`; never crash when the AnimInstance/mesh is missing.

### 3. Local hit feedback — new `UAAAHitFeedbackSubsystem : UWorldSubsystem` in `AAACombat` (client-side only: `GetWorld()->GetNetMode() != NM_DedicatedServer`)
Subscribes to `FAAACombatEvents`. Settings (add to `UAAACombatSettings`): `HitStopLightSeconds`, `HitStopHeavySeconds` (exist), `CameraShakeLight/Heavy` scales, `bEnableHitStop`, `bEnableCameraShake`.
- **Hit-stop**: freeze **only the two combatants** via `AActor::CustomTimeDilation = 0.03` on attacker and victim for the duration, restored by a world timer using *unscaled* real time (`FTimerManager` is affected by global dilation but not by `CustomTimeDilation`, so a normal timer on the world is fine — verify) with weak capture; overlapping hit-stops extend, never stack the restore wrongly; always restore on world teardown (`Deinitialize`). Do **not** use global time dilation. Skip if attacker is neither the local player nor target is the local player? No — apply whenever the local player is attacker or victim.
- **Camera shake**: only when local player is attacker or victim. Create a code-defined shake (no assets) per the 5.8 API; scale by `bHeavy` and damage; use `APlayerController::ClientStartCameraShake`.
- **Damage numbers**: keep a ring buffer `TArray<FAAADamageNumber{ FVector WorldPos; float Amount; double SpawnTime; bool bHeavy, bBlocked, bParried; }>` (max 32, 0.9 s life, rise 60 cm) exposed via `GetActiveDamageNumbers()` so a HUD (written in a later prompt) can draw them; add `void DrawDamageNumbers(AHUD* HUD)` that draws them with `HUD->DrawText`/`Canvas->K2_DrawText` projecting `Canvas->Project(WorldPos)`, scale and colour by type (white normal, orange heavy, grey blocked, cyan parried). Call it from `AAAAAHUD::DrawHUD` (create `DrawHUD` override if missing; keep the HUD's existing behaviour; **no slate brush allocation** per `Docs/after/BUGS.md` BUG-02).

### 4. Lock-on (`AAAAAPlayerController`)
- `ToggleLockOn()` on key **Q** (and mouse wheel click `MiddleMouseButton`); `CycleLockOn(int32 Dir)` on `Q`+... keep simple: `E`/`Tab`? **Tab is taken by the menu** → use `LeftBracket/RightBracket` for cycling.
- Target selection: candidates = actors within `LockOnRange` that have an ASC (via `IAbilitySystemInterface`) **or** implement team interface, not dead (`State.Combat.Dead`), not same team, inside `LockOnMaxAngleDegrees` of the camera forward, with line of sight (visibility trace from pawn eye to target chest). Score = angle weight + distance weight. Breaks automatically when target dies, leaves range ×1.3, or LOS lost > 1.5 s.
- While locked: each frame (`PlayerTick`) smoothly rotate `ControlRotation` toward the target chest (`FMath::RInterpTo`, speed ~8, clamp pitch −35..+25), and expose `AActor* GetLockedTarget() const` + `DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(FOnLockTargetChanged, AActor*, NewTarget)`. A stick/mouse flick > threshold gently overrides (accumulate input; if the player turns more than 30° away for 0.4 s, release).
- Make the pawn face the target while locked **only if** a clean hook exists (e.g. an orientation-intent API on the Mover/AAA pawn); otherwise only the camera locks and you note it in the report.
