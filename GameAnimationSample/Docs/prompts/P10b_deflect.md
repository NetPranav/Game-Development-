## Why this prompt exists (measured facts, verify by reading the code)
1. **Nobody reacts to hits.** `FAAAHitReactionSet` (`AAACombat/Public/AAACombatComponent.h`: Front/Back/Left/Right/Stagger/Death montages) is filled on `BP_PlayerCharacter` and on `BP_RREnemy_Greystone` (`/Game/RR/Greystone/AM_GS_*`), but **no C++ ever plays them** except `ARREnemy::OnDeath` (Death). `UAAACombatComponent::Multicast_OnHitConfirmed`, `OnBlockedEvent`, `OnParriedEvent`, `OnStaggeredEvent`, `OnDeathEvent` do not play any montage.
2. **Block/Equip/Unequip montages only play for `ACharacter`** (`Cast<ACharacter>(GetOwner())->GetMesh()`), but the player is a Mover `APawn` (not an ACharacter). So the player never plays block, deflect, hit-react or stagger animations. For the player the pose is produced by the **master skeletal mesh** (the first `USkeletalMeshComponent` owned directly by the pawn, which is hidden in game; the visible robot is a child-actor display mesh that copies its pose through an AnimBP). Montages must therefore be played on the **master mesh's AnimInstance** (slot `DefaultSlot`).
3. **No knockback on the player / enemy** is visible: `UAAAKnockbackSubsystem` (`AAAAbility/Private/AAAKnockbackSubsystem.cpp`) reacts to `FAAACombatEvents::OnHitConfirmed`, but players don't move when hit. Find out why (Mover pawn path via `UAAAMoverUtils::ApplyVelocityBurst`, tags/state, direction, magnitude from `UAAACombatSettings`, victim dead/invulnerable checks, `CustomTimeDilation` hit-stop swallowing the impulse, characters needing `LaunchCharacter`) and fix it so a hit visibly pushes the victim 80-150 cm away (light) / 180-260 cm (heavy) over ~0.2 s, and a **blocked** hit pushes the defender back 40-70 cm with the slide feeling grounded. Both for ACharacter (enemy, use `LaunchCharacter` or `ApplyVelocityBurst`'s ACharacter path) and Mover pawns.
4. **Deflect (parry) has no feedback**: tapping block opens `State.Combat.Parrying` for `UAAACombatSettings::ParryWindowSeconds`; `UAAAAttributeSet::PostGameplayEffectExecute` swallows damage when parrying and sends `GameplayEvent_Combat_Parried` to the attacker, which then gets `Staggered`. There is no spark, no clang, no animation on the defender, and no poise damage to the attacker.
5. **The player still has a health bar** drawn in `RRGame/Private/RRHUD.cpp::DrawMatchHUD`. The user wants it replaced by a screen effect like Resident Evil 8 (see `Docs/SPEC_BOSS.md`, "Visual feedback").

## Deliverable B — Sekiro deflect rules (AAAAbility + AAACombat)
Edit `UAAAAttributeSet::PostGameplayEffectExecute` (damage branch where `State_Combat_Parrying` is handled) and `OnParriedEvent`:
- On a successful deflect: (1) defender takes **zero** damage and **zero** poise damage (existing), (2) the *attacker* receives poise damage `UAAACombatSettings::DeflectPoiseDamage` (new UPROPERTY, default 38, category "AAA|Combat|Deflect") by applying the existing poise path (set `IncomingPoiseDamage` on the attacker's attribute set via the same GameplayEffect/`UAAAGE_Damage` mechanism the project already uses; read how poise damage is applied for normal hits and reuse it), (3) the attacker's current attack is cancelled and it plays a recoil: `HitReactions.Stagger`-like short stun of `ParryStaggerSeconds` (existing) — do **not** apply `Staggered` if the attacker is a boss with `State.Boss.Perilous` (see P11; for now just skip that check, P11 will add it), (4) fire a presentation event: add to `FAAACombatEvents` (`AAACombat/Public/AAACombatEvents.h`) `OnDeflected(AActor* Defender, AActor* Attacker, FVector ImpactPoint)` as a native multicast delegate like the others, broadcast from the authority place where the parry is resolved and again on clients through a `NetMulticast` on the defender's combat component (mirror how `Multicast_OnHitConfirmed` re-broadcasts).
- Block (hold) stays as is but: block stamina cost uses the existing formula; poise damage while blocking is 25 % (existing).
- Tapping block must feel like Sekiro: window 0.25 s (set the default of `UAAACombatSettings::ParryWindowSeconds`, if currently different, and mention it); holding block longer than 1.2 s without being hit makes block stamina drain 2x faster (add `BlockHoldStaminaDrainPerSecond` setting default 6 and apply it in the existing regen tick, only while Blocking) — keep this simple.
- `UAAAHitFeedbackSubsystem` (`AAACombat/Private/AAAHitFeedbackSubsystem.cpp`): subscribe to `OnDeflected` and `OnBlocked`: spawn a Cascade/Niagara VFX at the impact point (use soft object paths in `UAAACombatSettings`: `DeflectSparkEffect` default `/Game/ParagonGreystone/FX/Particles/Greystone/Abilities/Primary/FX/P_Greystone_Primary_Sparks.P_Greystone_Primary_Sparks` and `BlockSparkEffect` default `/Game/ParagonGreystone/FX/Particles/Greystone/Abilities/Primary/FX/P_Greystone_Primary_Impact.P_Greystone_Primary_Impact`; both `TSoftObjectPtr<UParticleSystem>` using `UGameplayStatics::SpawnEmitterAtLocation`; load synchronously on first use; null-safe), a short hit-stop (reuse the existing hit-stop code with 0.07 s for deflect, 0.04 s for block), a stronger camera shake for deflect, and a **clang sound slot** (`TSoftObjectPtr<USoundBase> DeflectSound`, `BlockSound`, played with `PlaySoundAtLocation`, default empty — the reviewer assigns later). Impact point: the weapon contact if available else midpoint between the two actors at chest height.
